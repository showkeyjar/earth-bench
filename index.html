快速了解

这是什么？
AI 帮您提前知道哪里可能有火灾、洪水、干旱、热浪、台风、寒潮、暴雪或滑坡风险；基准全量覆盖 8 类灾种、83 个用例。
怎么判断的？
多源数据融合：卫星+气象站+传感器，AI 对照国标阈值做二元决策（预警/不预警），并给出完整推理链。

关于 EarthBench

决策优先

传统气象系统回答"明天降雨多少毫米"，EarthBench 回答"今天是否应该启动洪水应急预案"。我们不预测数字，我们做决策。

多源融合

卫星遥感（NASA MODIS）、数值预报（ECMWF）、气象站（和风天气 API）、水文传感器——四类数据源交叉验证，单一来源的偏差被系统性修正。

AI 推理透明

每条预警不是黑箱输出。系统记录从数据采集到阈值对比、加权评分、最终决策的完整推理链，用户可以逐条审查 AI 的判断依据。

每日验证 · 历史锚定

每条决策都标注是否与 Ground Truth（基于国标阈值推导的标准答案）一致。真值函数另以 7 场真实灾害的公开记录回放验证——郑州 7·20、杜苏芮、通辽寒潮暴雪、重庆高温火险等，8/8 判定与现实一致。

EarthBench vs 传统天气预报

维度传统天气预报EarthBench
核心问题明天温度 35 度吗？今天该启动高温应急预案吗？
输出形态数值预测（温度、降水量）二元决策（预警 / 不预警）+ 置信度 + 推理链
数据来源单一气象模型卫星 + 气象站 + 传感器多源融合
验证方式预测值 vs 实际值决策结果 vs Ground Truth（命中/误报/漏报）
可解释性低（数值输出，无推理过程）高（完整推理链 + 证据卡片 + 阈值标注）

工作原理

每天 UTC 00:00 和 12:00（北京时间 08:00 和 20:00），系统自动执行四阶段流水线：

1

数据采集

从 QWeather API 获取 20 个监测区域的实时天气数据（温度、湿度、风速、降雨量），同时拉取逐小时和逐日预报用于趋势分析。QWeather 不可用时自动降级到内置场景数据。

QWeather API实时观测逐小时预报逐日预报

2

AI 决策

规则引擎首先基于国标阈值查表计算风险评分（动态权重归一化），完整证据链随决策归档。LLM 赛道独立运行：本地 Qwen3.6-35B（llama.cpp，无云调用）对同一场景做二次判定，与规则基线、平凡基线同表对比。

规则引擎国标阈值查表Qwen3.6-35BLLM 评测赛道

报告生成

为每个监测区域生成结构化决策记录，包含详细证据卡片（阈值对比 + 状态判定）、推理链条（从数据到决策的完整步骤）和 Ground Truth 验证结果。最终输出 Markdown 报告 + JSON 数据 + Atom Feed。

LLM 赛道

基准的真正使用方是 LLM Agent。提供两种信息口径：informed（给与真值同源的阈值表但不给判定——纯考推理组合）与 blind（不给阈值——考内化的标准知识）。后端为本地 Qwen3.6-35B（llama.cpp / Vulkan，无云调用）。首跑快照（informed，温度 0）：对抗 62%、基础 78%、全 83 例 0 解析失败；完整提示词与原始输出见 docs/llm-eval-carm.md。
